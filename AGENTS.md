# Libghosty Go Bindings

## Commands

- **Build:** `make build` (`go build ./...`; pure Go, no C toolchain)
- **Test:** `make test`
- **Vet:** `make lint`
- **Regenerate:** `make generate` (host platform) or `make generate-all`
  (every committed platform); needs Zig 0.17 and network access

## Layout

- The root package is the binding. It calls the translated library in
  `internal/vt`, whose files `vt_<goos>_<goarch>_<n>.go` and `consts.go`
  are generated by `generator.go`. Never edit generated files.
- `generator.go` downloads the pinned ghostty commit (the `ghosttyCommit`
  constant), applies `internal/patches/*.patch`, has Zig emit libghostty-vt
  as C, rewrites that C with the files in `internal/ccgo`, and translates
  it with ccgo/v4. `internal/libshim` holds the C functions the translation
  needs that modernc.org/libc lacks.
- After `make generate`, the C headers of the pinned commit are at
  `/tmp/libghostty-generate/out-<goarch>/include/ghostty/`.
- Generated code is committed for linux/amd64 and linux/arm64. Add a
  platform by adding it to `zigTargets` in `generator.go` and `TARGETS`
  in the Makefile.

## Code Guidelines

- Use a heavy commenting style that explains what/why clearly.
- Comment every exported function, type, field, etc.
- Types should be in the same filename as the C header, by default.
  If they're already moved, keep them where they are. For example,
  `color.h` types should go in `color.go`.
- If a type is a thin layer over a C type, comment with what
  C type it corresponds to, e.g. `C: GhosttyResult`
- Define constants by their C reference, e.g.
  `DAConformanceVT100 = vt.GHOSTTY_DA_CONFORMANCE_VT100`. Don't
  hardcode values.
- Calls into `internal/vt` follow the conventions in `CCGO.md`: a TLS
  from `getTLS` per call, C pointers as `uintptr`, out-parameters in
  `tls.Alloc` memory (never the address of a Go variable), callbacks as
  top-level functions registered with `vt.Fp` and `handle` userdata.
- When a C API uses `GhosttyString` with `len=0`, libghostty treats
  the pointer as garbage, so no nil special-casing is needed.
