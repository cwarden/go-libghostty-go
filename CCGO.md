# ccgo Port Checklist

Replace the cgo backend with Go code generated by ccgo/v4 from the C that
Zig's C backend emits for libghostty-vt, as remindgo does for Remind.
Decisions: generate and commit Linux amd64 and arm64 only; remove cgo
entirely.

## Porting conventions

The cgo files are set aside as `<name>.go.cgo`. To port one, `git mv` it
back to `<name>.go` and rewrite it by these rules. Keep the exported Go
API, its documentation and the `// C: ...` comments; change comments only
where they describe cgo. Use tabs; run gofmt.

- Remove the cgo preamble and `import "C"`. Import
  `go.mitchellh.com/libghostty/internal/vt` and, when needed,
  `modernc.org/libc`.
- Calls: `C.ghostty_x(args)` becomes `vt.Xghostty_x(tls, args)`. Each
  exported function or method that calls into vt takes a TLS for its
  duration: `tls := getTLS(); defer putTLS(tls)`. A callback receives the
  TLS of the call in progress as its first parameter and passes that one
  on when it calls into vt.
- Types: `C.GhosttyFoo` becomes `vt.GhosttyFoo`. Struct fields carry an F
  prefix: `.ptr` is `.Fptr`. ccgo renames fields that are Go builtins, so
  `GhosttyString.len` is `.Flen1`. Check a type's fields with
  `grep -A8 '^type GhosttyFoo = ' internal/vt/*.go`. Every struct type is
  an alias of an unnamed struct, so two types with the same fields are the
  same Go type. Enum types are aliases of integer types; a cast such as
  `C.GhosttyPasteSource(x)` becomes `vt.GhosttyPasteSource(x)`.
- Unions: the generator emits a C union as a struct whose members are
  zero-length arrays at offset 0 (they type the address and keep the
  alignment) plus `F__ccgo_union`, a byte array of the union's size that
  holds the storage. No member is a real field: read or write a member by
  casting the union's address:
  `(*vt.GhosttyTerminalUnknownOscSequence)(unsafe.Pointer(&seq.Fvalue))`.
  (ccgo's own representation keeps one member as a real field, whose
  trailing padding Go struct copies need not preserve, which lost bytes of
  the other members when Zig copied a tagged union by value.)
- Constants: `C.GHOSTTY_X` becomes `vt.GHOSTTY_X`.
- Scalars: `C.size_t(x)` is `uint64(x)`; `C.uint16_t`, `C.uint32_t`,
  `C.int32_t`, `C.uint8_t` are `uint16`, `uint32`, `int32`, `uint8`;
  `C.int` is `int32`; `C.double` is `float64`; `C.bool(b)` is `cBool(b)`
  (ccgo.go); a C bool value `v` is a `uint8`, read as `v != 0`;
  `cTrue`/`cFalse` are the constants.
- Pointers: a C pointer is a `uintptr`; `nil` is `0`. A `*C.T` field or
  parameter becomes `uintptr`; dereference with
  `(*vt.T)(unsafe.Pointer(p))`. `C.sizeof_T` is `unsafe.Sizeof(vt.T{})`.
  A C-string argument comes from `libc.CString(s)` (returns `uintptr,
  error`), freed with `libc.Xfree(tls, p)`.
- Never pass the address of a Go variable or struct to vt. The translated
  code runs on the goroutine's stack, which the runtime may move during
  the call, after which a `uintptr` to a stack variable points at the old
  copy. Out-parameters and scratch structs go in TLS stack memory:
  `n := int(unsafe.Sizeof(vt.T{})); p := tls.Alloc(n); defer tls.Free(n)`,
  used through `(*vt.T)(unsafe.Pointer(p))`. Free in LIFO order with the
  same size (defer keeps the order). TLS memory is not zeroed; clear it
  when libghostty may read a field before writing it. Memory that outlives
  the call comes from `Alloc`/`allocZeroed` (alloc.go).
- Byte slices passed as input data: `addr, unpin := pinBytes(p); defer
  unpin()` (p must be non-empty); pinning keeps the array on the heap,
  where it does not move.
- Reading C memory: `C.GoBytes(p, n)` is `goBytes(p, n)` (ccgo.go; it
  copies, while `libc.GoBytes` returns a view of the C memory);
  `C.GoString(p)` is `libc.GoString(p)`; `C.GoStringN(p, n)` is
  `string(libc.GoBytes(p, n))`; a view is
  `unsafe.Slice((*T)(unsafe.Pointer(p)), n)`.
- Callbacks: the C function pointer for a Go function is `vt.Fp(fn)`. fn
  must be a top-level function (never a closure or method value: its
  pointer is stored in C memory, which the collector does not scan) with
  the signature `func(tls *libc.TLS, <C params>) <C result>`, C types
  mapped as above (struct parameters by value as `vt.GhosttyX`, bool as
  `uint8`, pointers as `uintptr`). The userdata is a `handle` (ccgo.go):
  `newHandle(v)`, `handle(userdata).value().(*T)`, `h.delete()`; pass
  `uintptr(h)` as the `void*`. Calling a C function pointer `fp`:
  `(*(*func(*libc.TLS, A, B) R)(unsafe.Pointer(&struct{ uintptr }{fp})))(tls, a, b)`.
  Replace the `set_*`/`clear_effect` C helpers with
  `vt.Xghostty_terminal_set(tls, t.ptr, vt.GHOSTTY_TERMINAL_OPT_X, vt.Fp(goXTrampoline))`
  and `vt.Xghostty_terminal_set(tls, t.ptr, opt, 0)`.
- Reader and writer descriptors: `bridge.cWriter()`, `bridge.cReader()`
  and `bridge.cMIMEReader()` in io.go replace the helpers of go_io.h.
- Check with `go build .` and `go vet .`. Errors in files that are not
  yours are expected until every file is ported.
